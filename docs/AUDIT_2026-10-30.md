# Complément d’audit GUI — 30 octobre 2026

Les limitations signalées dans la revue ont été traitées dans le projet Pulpit et vérifiées
sur son instance Compose de développement. La production n’a pas été modifiée.

## Corrections et capacités exposées

- Les sélecteurs et catalogues parcourent toutes les pages Pulp ; les limites de 100/10 000
  objets ne tronquent plus les choix. Recherches, types et états réinitialisent la pagination.
  Une page devenue vide après suppression revient sur une page valide.
- Toutes les tâches actives sont conservées, avec vingt tâches terminées récentes. Le rechargement
  retrouve les opérations actives dans Pulp/core et résout les PRN pour retrouver leurs ressources.
  Le compteur du tiroir correspond aux opérations actives.
- Les groupes attendent la fin du dispatch et de tous leurs enfants. Les échecs restent visibles,
  les changements partiels sont rafraîchis, et un lien permet de consulter tous les enfants.
- Les requêtes de copie container acceptées sont enregistrées immédiatement ; une erreur sur
  l’autre requête ne les masque plus. La reprise du même formulaire renvoie les seules requêtes
  manquantes. Les erreurs originales restent consultables.
- Les versions conservées sont copiables, y compris les anciennes. Les formulaires proposent
  la sélection du contenu RPM/Ansible, des tags, digests et types de manifests container,
  ainsi que les options de résolution des dépendances RPM.
- « Sync with options… » complète la synchronisation rapide : remote ponctuel, miroir,
  politiques RPM, exclusions et optimisation. Un miroir demande confirmation ; le filtre
  container de présence d’une signature n’est pas présenté comme une vérification cryptographique.
- La création non-RPM et l’édition de tous les formats utilisent un éditeur partagé pour le nom,
  le chemin, les versions/publications, les gardes et la visibilité. La création RPM conserve
  sa préparation spécifique de configuration/publication et partage les contrôles d’accès.
  Les distributions figées restent visibles dans leur dépôt même avec `repository: null`.
- La reconnexion d’une distribution orpheline demande confirmation, vérifie de nouveau sa cible
  et conserve ses réglages d’accès. Une distribution active ou un conflit entre formats est protégé.
- Les suppressions container vérifient leur conséquence native : une URL figée ne supprime pas
  le dépôt ; le dernier rattachement direct peut le supprimer. Le formulaire attend cette vérification.

## Upload manuel de plusieurs RPM

Le formulaire RPM accepte plusieurs fichiers et conserve une file visible avec retrait avant
envoi, erreurs individuelles et reprise des seuls fichiers rejetés. Les contenus acceptés
sont rattachés en une seule tâche Pulp ; une erreur de rattachement conserve les références
déjà uploadées pour éviter de renvoyer les corps. La fin de l’envoi HTTP reste distincte
de la fin de la tâche de signature et de modification du dépôt.

Le test natif couvre aussi l’ajout manuel d’un lot contenant une ancienne signature fournisseur
et un RPM non signé. La tâche `signed_add_and_remove` réussit avec le script `--resign`, puis
les téléchargements et métadonnées se vérifient cryptographiquement avec la clé du dépôt.
La correction du script était encore absente de l’ancienne release de production signalée.

## Deux défauts natifs Pulp corrigés

Le plugin dérivé `pulpit-api-compat` conserve la responsabilité côté Pulp :

- pulp_container 2.29.0 renvoie une URL de garde redirect qu’il refuse ensuite en modification.
  La correction vise le nom de vue obsolète, conserve le modèle et les permissions natifs, et
  n’autorise pas de garde HTTP générique sur un registre.
- pulp_rpm 3.38.5 laisse les groupes prune/ACS en dispatch incomplet après la fin des enfants.
  La correction appelle la finalisation native au bon endroit, sans transformer un échec en succès.
  Les groupes déjà finalisés sont laissés tels quels ; l’historique ancien n’est pas réécrit.

Les correctifs sont isolés de la politique des chemins et du module de signature. Ils doivent
être revérifiés lors d’une mise à jour de Pulp. Les anciens hooks de création remplacés par
l’éditeur partagé sont supprimés ; l’aide intégrée et les consignes du dépôt sont mises à jour.

## Vérifications

- `make check` : **881 tests frontend**, formatage, ESLint, TypeScript et build réussis.
- **12 tests natifs de compatibilité/distribution** : routes de garde, refus d’un modèle de garde
  incompatible, exceptions de dispatch et finalisation de groupe.
- **12 tests natifs de signature** rejoués sur l’image mise à jour, dont la vérification
  cryptographique des RPM/métadonnées, on-demand, cache, échec et reprise.
- Knip : aucun fichier ni export d’exécution inutilisé après nettoyage.
- Playwright : **113 tests distincts validés** sur le dev, dont l’upload multiple et sa reprise
  sur petit écran. La passe complète valide 109 tests ; un contrôle de géométrie Administration
  échoue pendant le chargement des fontes et empêche trois tests suivants de démarrer.
  Après ajout de l’attente des fontes, les quatre scénarios Administration passent **trois fois
  de suite** (13 tests avec l’authentification de préparation). Le seuil géométrique reste inchangé.

La livraison nécessite les deux images **Pulp et Pulpit**. Les seuls réglages globaux temporaires
utilisés pour les tests sont la rétention de l’historique et les domaines de fixtures du proxy ;
leurs valeurs d’origine ont été restaurées après les tests, et le proxy a été rechargé.
